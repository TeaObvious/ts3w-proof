## Active lot changes and frame ordering

Setting the same GUID returns immediately. On a change, the manager resolves the old GUID and accepts the virtual type value `1`; modes `201`, `202`, and `204` perform an additional old-lot operation. It then notifies old objects that their lot is no longer current, stores the new GUID, resolves and notifies the new type-1 lot, and sends message `0x04891b02` with the new GUID. An unresolved GUID is still stored. This sequence neither calls the detail-request setter nor waits for assets. [ASM](../../evidence/native/functions/00C62B10_WorldManager_SetActiveLot.asm) ([C](../../evidence/native/functions/00C62B10_WorldManager_SetActiveLot.c))

The current-lot notification enumerates objects on each floor and forwards its byte to components selected by mask `0x011ea2a8`. The original allocation label is `Lot/SetIsCurrent/objectsOnLevel`. This component notification is distinct from the lot's requested-detail byte. [ASM](../../evidence/native/functions/00ACAD10_Lot_NotifyObjectsCurrent.asm) ([C](../../evidence/native/functions/00ACAD10_Lot_NotifyObjectsCurrent.c))

The frame update obtains a camera vector through `0x0095fde0` and a separate vector directly from camera `+0x60`. Their complete original names have not been recovered. Terrain streaming runs first with the helper's vector and an admission Boolean equivalent, for finite values, to `camera[+0x64] <= manager[+0xe8] || manager[+0xda] != 0`. Lot arbitration follows unless manager `+0x258` suppresses that subcall. It receives `deltaSeconds`, the helper vector, logical-not camera byte `+0x6df`, and the camera pointer. The meaning of that camera byte beyond this observed use remains open. In particular, it must not be conflated with the independent WorldManager `+0xda` input. [Frame ASM](../../evidence/native/functions/00C6D3B0_WorldManager_UpdateFrame.asm) ([C](../../evidence/native/functions/00C6D3B0_WorldManager_UpdateFrame.c))

`WorldManager_UpdateLotDetailRequests` consumes **four** stack arguments (`RET 0x10`), including the unused camera pointer. Earlier untyped decompilation omitted that fourth argument. It copies the 16-byte vector into manager `+0x3a0` **before** checking freeze `+0xd9`. A frozen update therefore remembers the vector, skips lot arbitration, and leaves the preceding terrain update and the rest of the frame update running. [ASM](../../evidence/native/functions/00C6C0D0_WorldManager_UpdateLotDetailRequests.asm) ([C](../../evidence/native/functions/00C6C0D0_WorldManager_UpdateLotDetailRequests.c))

## Imposter pass

When `+0xd8` is nonzero and arbitration is not frozen, the manager rebuilds dirty lot buckets and scans its global lot pointer vector. It requests detail for exactly the resolved active-GUID lot of virtual type `1` **if `+0xda` is nonzero**; every other nonnull lot receives a false request. If `+0xda` is zero or the active lot cannot be resolved, every nonnull lot receives false. This pass bypasses normal distance scores, numeric priorities, admission counts, and promotion throttling. [ASM](../../evidence/native/functions/00C69EC0_WorldManager_ApplyImposterLotDetailRequests.asm) ([C](../../evidence/native/functions/00C69EC0_WorldManager_ApplyImposterLotDetailRequests.c))

That conditional contract does not by itself establish which gameplay transition sets either flag. The managed caller evidence is required before asserting that a particular town/map-view transition clears active-lot detail.

## Normal arbitration

### Motion suppression and priorities

When the supplied `allowProximity` Boolean is true, the update computes camera displacement length divided by `deltaSeconds`; when `abs(deltaSeconds) <= binary32 epsilon`, its sample is zero. A ten-sample list supplies the average. Only an **ordered greater** comparison against manager `+0xec` suppresses arbitration; equality and unordered values do not take that return. The remembered vector has already been updated. [ASM](../../evidence/native/functions/00C6C0D0_WorldManager_UpdateLotDetailRequests.asm) ([C](../../evidence/native/functions/00C6C0D0_WorldManager_UpdateLotDetailRequests.c))

For each nonnull lot not suppressed by its `+0xc9` byte:

1. The active-GUID type-1 lot gets priority `4` only when manager mode is `201`, `202`, or `204`, map-active `+0xda` is nonzero, or lot `+0x4bc` is nonzero.
2. Otherwise, the lot containing the supplied camera XZ gets `3` when `allowProximity || mapActive` enables that lookup.
3. Otherwise, use its signed Int32 priority at `+0xc4`.

The bridge stores all 32 priority bits without validation. Original managed values are `None=0`, `PlayerSim=1`, `Home=2`, `Camera=3`, and `Active=4`; native ranking compares these **numerically as signed integers**, despite the managed `[Flags]` attribute. Ordinary managed producers are documented in the [caller guide](map-view-managed-callers.md). [Bridge ASM](../../evidence/native/functions/00788990_ScriptCore_World_World_LotSetDetailPriority.asm) ([C](../../evidence/native/functions/00788990_ScriptCore_World_World_LotSetDetailPriority.c)), [setter ASM](../../evidence/native/functions/00AAFF10_Lot_SetDetailPriority.asm) ([C](../../evidence/native/functions/00AAFF10_Lot_SetDetailPriority.c)), [getter ASM](../../evidence/native/functions/00AAFF00_Lot_GetDetailPriority.asm) ([C](../../evidence/native/functions/00AAFF00_Lot_GetDetailPriority.c))

The lot constructor initializes requested detail `+0xc1`, readiness byte `+0xc2`, priority `+0xc4`, suppression `+0xc9`, and override `+0x4bc` to zero. [ASM](../../evidence/native/functions/00AC0B60_Lot_Construct.asm) ([C](../../evidence/native/functions/00AC0B60_Lot_Construct.c))

### Distance and ordering

The original metric selector at `0x011853f8` is file-initialized to `1`. This path transforms the camera vector into lot coordinates, computes `max(0, -x, -z, x-width, z-depth)`, then squares it. For finite ordinary coordinates this is **squared Chebyshev distance to the lot rectangle**, not Euclidean nearest-edge distance. Width/depth are signed Int32 values converted with `CVTSI2SS` at `0x00c62900`/`0x00c628aa`. The final binary32 score returns in x87 ST0 through `FLD` at `0x00c62afb`; that return instruction is separate from the dimension conversion. The alternate selector-zero path computes horizontal squared distance to the lot bounds' center, applying a moving-lot transform when present. [Score ASM](../../evidence/native/functions/00C62850_WorldManager_ComputeLotDetailScore.asm) ([C](../../evidence/native/functions/00C62850_WorldManager_ComputeLotDetailScore.c)), [original constants](../../evidence/native/map-view-lot-detail-data.tsv)

The helper writes unbiased `distanceSquared` and returns an x87 score. If requested detail `+0xc1` is already nonzero, it subtracts manager `+0xe0` from that **score**, giving a construction-default bias of `8` in squared-distance units. Radius eligibility still uses the unbiased value. Higher signed priority sorts first; within a priority, a smaller finite score sorts first. Equal scores have no stable-order guarantee.

Each score record is 16 bytes: `{lot pointer, float distanceSquared, int32 priority, float score}`. The vector is resized to the total lot-list length and zero-initializes appended records; skipped null/suppressed lots leave zero tail records. It is not merely a capacity reservation. The selected prefix is partially sorted; the remaining tail is not globally sorted. [Resize ASM](../../evidence/native/functions/00C665C0_LotDetailScores_Resize.asm) ([C](../../evidence/native/functions/00C665C0_LotDetailScores_Resize.c)), [partial-sort ASM](../../evidence/native/functions/00C63B80_LotDetailScores_PartialSort.asm) ([C](../../evidence/native/functions/00C63B80_LotDetailScores_PartialSort.c))

The complete comparator helpers retain signed index/priority arithmetic and the original floating-point branches: [make-heap ASM](../../evidence/native/functions/00C62E30_LotDetailScores_MakeHeap.asm) ([C](../../evidence/native/functions/00C62E30_LotDetailScores_MakeHeap.c)), [adjust-heap ASM](../../evidence/native/functions/00C61B10_LotDetailScores_AdjustHeap.asm) ([C](../../evidence/native/functions/00C61B10_LotDetailScores_AdjustHeap.c)), [push-heap ASM](../../evidence/native/functions/00C5FB00_LotDetailScores_PushHeap.asm) ([C](../../evidence/native/functions/00C5FB00_LotDetailScores_PushHeap.c)), [sort-heap ASM](../../evidence/native/functions/00C62EA0_LotDetailScores_SortHeap.asm) ([C](../../evidence/native/functions/00C62EA0_LotDetailScores_SortHeap.c)). A total ordering of NaNs is not established.

### Admission count and promotion throttle

Let `M` be the unsigned maximum active count, `T` the signed force-priority threshold (file default `1`), and `N` the resized score-vector length. When `allowProximity` is true, priorities below `T` become zero and the admission budget is `min(M,N)`. When false, let `S` count priorities `>=T` and `H` count priority `4` entries that also pass that threshold; the budget is `min(max(min(S,M),H),N)`. These are original unsigned count/budget comparisons. Pointer-typed count locals in the displayed C are decompiler artifacts. [ASM](../../evidence/native/functions/00C6C0D0_WorldManager_UpdateLotDetailRequests.asm) ([C](../../evidence/native/functions/00C6C0D0_WorldManager_UpdateLotDetailRequests.c))

The scan demotes nonnull entries after the admitted count reaches the budget. A priority `<=0` entry also requires **strictly** `distanceSquared < radiusSquared`. At equality it is rejected. Original `COMISS radiusSquared,distanceSquared; JBE` also rejects unordered values; the simplified decompiler expression omits that NaN case. Positive priorities bypass this radius test. Demoted entries do not increment the admitted counter.

Promotion throttling is enabled only when global `0x011edbc0` is nonzero and `M <= 0x01185328` (file threshold `12`). With throttling enabled, at most one new request is admitted per pass; an existing pending detail operation can defer all new requests. Existing true requests remain true, and demotions still run. The pending query scans requested lots and returns low-byte true when lot `+0xc2` is zero or the original streaming query `0x00700c20` reports pending for its GUID. Its byte getter is retained separately. The full meaning and writers of readiness `+0xc2`, and all downstream resource completion conditions, remain open. The actual GUID lookup and selected `0x42` flag consumer are bounded in [lot-detail dispatch and pending queries](lot-detail-dispatch-and-pending.md). [Pending-query ASM](../../evidence/native/functions/00C69E30_WorldManager_HasPendingLotDetail.asm) ([C](../../evidence/native/functions/00C69E30_WorldManager_HasPendingLotDetail.c)), [byte-getter ASM](../../evidence/native/functions/00D43520_Lot_ReadDetailReadinessByte.asm) ([C](../../evidence/native/functions/00D43520_Lot_ReadDetailReadinessByte.c))

Manager `+0xdb` receives the pass's deferred-promotion byte when throttled, or the pending-query result otherwise. Early returns and the imposter pass do not recompute it. It is not a universal all-assets-loaded indicator.

## Requests, remote work and object policy

`Lot_SetDetailRequested` returns without action when the byte is unchanged or lot `+0xc9` suppresses changes. Otherwise it stores `+0xc1` **before** submitting remote work. True selects the promotion method with flags `0,0`; false selects the demotion method with flag `0`. It then sends message `0x0421fefd` carrying the requested byte. The submission result is ignored, and there is no resource wait. [Setter ASM](../../evidence/native/functions/00AC1250_Lot_SetDetailRequested.asm) ([C](../../evidence/native/functions/00AC1250_Lot_SetDetailRequested.c)), [requested-byte getter ASM](../../evidence/native/functions/00AAFEF0_Lot_GetDetailRequested.asm) ([C](../../evidence/native/functions/00AAFEF0_Lot_GetDetailRequested.c)), [message ASM](../../evidence/native/functions/00AB32D0_Lot_SendManagerMessage.asm) ([C](../../evidence/native/functions/00AB32D0_Lot_SendManagerMessage.c))

The two generic remote-call helpers allocate a `Services/RemoteMethodCall` record, install the object/method/user data and one or two flag bytes, submit via `0x007d9b10`, and release the local record reference. Only AL carries their result. The selected dispatcher has a same-thread inline path and a separate two-flag job submission/wait path, now bounded in [lot-detail dispatch and pending queries](lot-detail-dispatch-and-pending.md). The complete target callback, retention of target objects and completion notification remain separate open boundaries. [Two-flag ASM](../../evidence/native/functions/00ABD400_RemoteMethodCall_SubmitTwoFlagMethod.asm) ([C](../../evidence/native/functions/00ABD400_RemoteMethodCall_SubmitTwoFlagMethod.c)), [one-flag ASM](../../evidence/native/functions/00ABD490_RemoteMethodCall_SubmitOneFlagMethod.asm) ([C](../../evidence/native/functions/00ABD490_RemoteMethodCall_SubmitOneFlagMethod.c))

The promotion method clears the requested byte and returns if suppression became active before execution. Otherwise it brackets original events `0x04c55e8c`/`0x04c55efa` and applies the per-object display-detail policy. That policy checks the original component mask, special-object classification, signed level bounds and `INT_MAX` sentinel, component flags, and the lot's display-level cap before choosing its downstream submission path. This is selective object work. [Promotion ASM](../../evidence/native/functions/00AC01E0_Lot_ApplyDetailRequestToObjects.asm) ([C](../../evidence/native/functions/00AC01E0_Lot_ApplyDetailRequestToObjects.c)), [object-policy ASM](../../evidence/native/functions/00ABE9F0_Lot_ApplyObjectDisplayDetail.asm) ([C](../../evidence/native/functions/00ABE9F0_Lot_ApplyObjectDisplayDetail.c))

The demotion method scans existing object pointers and dispatches object event `0xc` only for its original force/lot/object predicates. It neither destroys every object nor clears the lot vector. The exact downstream event's asset-lifetime behavior remains outside this bounded review. [ASM](../../evidence/native/functions/00AB3310_Lot_DispatchDetailDemotionToObjects.asm) ([C](../../evidence/native/functions/00AB3310_Lot_DispatchDetailDemotionToObjects.c))

## Terrain and cleanup boundaries

Terrain streaming receives its near-detail Boolean before lot arbitration. It stores that input and the camera vector separately, then assigns desired leaf LOD `1` by default. Only an enabled input and strict Chebyshev distance below its threshold select mode mapping `0→4`, `1→3`, `2→2`; disabled input, equality, unordered values, or other modes retain `1`. Current leaf LOD `+0x5c` and desired LOD `+0x60` are separate fields; the remaining full function advances original terrain streaming/material work. This is a terrain-leaf policy, with its own thresholds and states. [ASM](../../evidence/native/functions/00C84570_Terrain_UpdateStreamingTilesFromCamera.asm) ([C](../../evidence/native/functions/00C84570_Terrain_UpdateStreamingTilesFromCamera.c))

One native dirty-world flush is also a cleanup caller. With world dirty byte `+0x46` clear it returns true immediately. Otherwise, if heightmap-manager data `manager[+0x54][+8]` was absent before temporary preparation and becomes present afterwards, the function eventually invokes `0x00c63410(this, Force=0)`. It clears dirty state and its dirty-rectangle list before that call, ignores cleanup's result, and returns the original flush result's bit zero. This proves a conditional temporary-data cleanup path; it does not establish that every map-view change runs it. [ASM](../../evidence/native/functions/00C6BB00_WorldManager_FlushDirtyWorldData.asm) ([C](../../evidence/native/functions/00C6BB00_WorldManager_FlushDirtyWorldData.c))

### Verification and remaining questions

Executed offline checks verified the complete selected function envelopes and independent disassembly against original file bytes. The C files are actual annotated Ghidra output. Static proof separates requested detail, priority, camera state, active identity, terrain desired LOD and readiness. No runtime memory measurement, live map-view transition, remote-dispatch timing, fresh-process reload, or completed asset-residency test was performed. Exact downstream object-event effects and readiness/streaming completion remain open.
