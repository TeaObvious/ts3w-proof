## Actual class versus managed custom identity

Its actual72-byte body ends in either a plain RET failure or a tail JMP to property-interface virtual14 hex, so it is caller-clean; the old one-byte Ghidra body/stdcall metadata/bounded80-byte window did not describe the function. It calls the actual global service, checks the handle's high byte30, resolves through service virtualCC, requires a nonnull object and QueryEEC58382 property interface. A missing kind/object/interface returns0; success preserves the class getter's full EAX value. It does not use a CLR runtime type name or FNV string fallback.

Their primary/property virtual14 slots join actual native class getters: CustomWindow03AA4128, CustomButton03AA4138, CustomDialog03AA4148. GetCustomControlID separately selects proxy/property/custom interfaces and is not interchangeable with GetClassID. ## Actual custom factory registration and removal

RegisterCustomControlFactory has two caller-clean stack DWORDs, class ID and registration control; only the latter's low byte is tested. Nonzero calls the actual registration helper; zero calls unregistration. Each branch cleans its own pushed helper argument and returns plain RET. No failure value is promised by this void managed binding.

Registration allocates8 bytes, installs the actual wrapper vtable and stores class ID at+4 when nonnull. It then obtains the native factory service and invokes virtual4(wrapper,0). Allocation-null still calls the service with two zeros; no safe-success guarantee is inferred. The allocator call physically pushes six DWORDs (8,label,0,0,0,0) and cleans24 bytes. Actual Ghidra C retains a foreign three-argument prototype; its plate explicitly records this decompiler defect. No unrelated allocator signature was changed to improve display.

The wrapper vtable selects its destructor, actual identity-output method, the already proven007E4010 proxy factory, and an existing registration-name callback. Identity output receives ECX wrapper, output pointer and a fullDWORD capacity/control word; RET8. It writes wrapper+4 only when both words are nonzero, but returns full EAX1 even when either is zero. This is neither a zero-argument getter nor a false-on-null API. Removal performs service virtual14 lookup(ID), then only on a nonnull wrapper calls service virtual8 removal before wrapper virtual0(1) destruction.
