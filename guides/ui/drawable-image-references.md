## Actual ABI versus remaining decompiler defects

Corrected prototypes are original physical ABI, not a claim that every resulting C expression is reliable. The actual database annotations and C explicitly record remaining defects:

- Getters load handle/property/component at saved-ESP+5C/+60/+64. Their C still substitutes windowHandle for the descriptor property and propertyIdentity for the selected component. Those shifted expressions are not original behavior.
- Setter uses second/third/fourth original stack words for property/component/image. Saved EBX/EBP alter their local ESP offsets: property77BF69, image77BFA5, component77BFCF. C still shifts those roles. Physical four arguments and plain RET govern.
- Load's C shows an apparent unaff_ESI release although77F6B0 reloads the actual captured resource; prints zero-argument fallback although77F789/78B push flag1/key and caller cleans8; prints three allocator arguments although six words and24byte cleanup are physical. Foreign helper/indirect signatures were deliberately not guessed for cosmetic C.

Native descriptor lookup/read/write is independently documented by the complete reused [lookup ASM](../../evidence/native/functions/00511CA0_NativePropertyContext_FindDescriptor.asm) ([pseudocode](../../evidence/native/functions/00511CA0_NativePropertyContext_FindDescriptor.c)), [read ASM](../../evidence/native/functions/00511AA0_NativePropertyDescriptor_Read.asm) ([pseudocode](../../evidence/native/functions/00511AA0_NativePropertyDescriptor_Read.c)), [write ASM](../../evidence/native/functions/00511D40_NativePropertyDescriptor_Write.asm) ([pseudocode](../../evidence/native/functions/00511D40_NativePropertyDescriptor_Write.c)). The setter's real typed writer retains/releases pointer-array elements; raw handle replacement is not full native callback equivalence.

## Independent references and actual zero dispatch

The shared release bridge [007796E0 ASM](../../evidence/native/functions/007796E0_ScriptCore_UIManager_UIManager_DestroyDrawableImpl.asm) ([pseudocode](../../evidence/native/functions/007796E0_ScriptCore_UIManager_UIManager_DestroyDrawableImpl.c)) selects a kind30 object and invokes its primary+4. StdDrawable primary00FC0840 slots0/+4/+8/+C are516C20/539560/53E700/53DB30. Its query delegation returns the complete primary for the getter, so the selected counter is complete+8.

The existing [retain thunk ASM](../../evidence/native/functions/00516C20_CountedReference_Retain.asm) ([pseudocode](../../evidence/native/functions/00516C20_CountedReference_Retain.c)) reaches [increment ASM](../../evidence/native/functions/0040A300_CountedReference_Retain.asm) ([pseudocode](../../evidence/native/functions/0040A300_CountedReference_Retain.c)). The [release thunk ASM](../../evidence/native/functions/00539560_CountedReference_ReleaseAndDispatchZero.asm) ([pseudocode](../../evidence/native/functions/00539560_CountedReference_ReleaseAndDispatchZero.c)) reaches [decrement/zero-dispatch ASM](../../evidence/native/functions/00504BC0_CountedReference_ReleaseAndDispatchZero.asm) ([pseudocode](../../evidence/native/functions/00504BC0_CountedReference_ReleaseAndDispatchZero.c)). The latter calls primary+8(flag1) only when the decremented DWORD equals0. There is no atomic prefix or overflow/underflow guard in those selected bodies. Counter2→1 cannot dispatch the destructor;1→0 can.

The exact paired-bank destructor timing matters under callback reentrance. In each iteration it reads/releases bank10, reads bank30, clears bank10, releases that captured bank30 pointer, clears bank30, then advances. Reading bank30 before the first release or clearing bank10 before the bank30 read would change behavior. The selected array setter differs again: retain new, release old, then publish the new slot. No blanket retain/release ordering should replace these actual paths.

## Current adaptation and corrected ownership case

Current key-only LoadUiImage, row-presence ownership approximation, unknown/untracked handles, per-host tracking versus global payloads, external thumbnail/world/portrait holds and actual renderer retirement remain distinct from native internals. A concrete current defect was identified: two GetDrawableProperty acquisitions, removal of the owning layout, then one DestroyDrawable decremented the script count2→1 but still removed all drawable state/images. The corrected owner preserves remaining script-held drawables, as the actual native zero-dispatch and independent managed wrappers require. Its final release can retire nested resources. This is not a claim of a demonstrated finalizer-thread race or universal concurrency repair.
