## Shutdown ordering and reentrance

WindowBase Shutdown removes every procedure before its later children/member releases. Its envelope includes seven explicit unowned alignment bytes515B99..9F skipped by control flow. Procedure removal calls service50B9C0 when applicable, searches the actual procedure list, creates message0x1001 with source/destination0, calls procedure0x18, releases the procedure and then removes/deallocates its list node. Actual callbacks occur before that list retirement.

For0x1001 the script procedure tests4097 membership and conditionally calls ProcessEvent. It rereads Host and invokes the separate shutdown bridge even when4097 was absent. Only afterwards does it clear attached window and ask the registry to retire this procedure. Registry retirement checks both the window key and the exact procedure pointer, preserving an unrelated replacement under the same key. The separate shutdown bridge guards service/current callback/service0x34, creates a kind0x30 handle, passes one UInt32 variant through the fourth callback, destroys the return, releases the handle and destroys its argument. It has no ordinary receiver acquire virtual0 step.

The original managed shutdown callback removes the script registry row; WindowBase shutdown accessors register4097, while Tick accessors register12. UIManager.OnInternalWindowShutdown removes original tag and tooltip callback entries. OnWinDetach separately drops an allowed cached wrapper then calls original DeRegisterAll. Those managed policies remain separate from native procedure/mask/handle mechanics. Native selected removal and notification are synchronous; these full bodies contain no CLR managed-thread marker or shutdown FIFO.
