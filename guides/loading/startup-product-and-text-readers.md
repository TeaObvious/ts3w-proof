## LoadingText resource and row admission

The text reader constructs a resource key for LoadingText plus the product suffix, type 0333406C/group 0, and falls back to the base name only when the specific resource lookup is absent. It obtains the original XML stream and adapter, searches for an exact UTF16 LoadingText element, initializes count to zero, and asks the Int32 attribute helper for one value. The loop runs only for a positive declared count. It advances the adapter, copies the current element name, and compares equal-length row names to Text through the low-byte case-folded comparer. It requests localizedName for each visited row and maintains cumulative read success: once resource/reader/root/count/row/name/attribute admission becomes false, later rows are not appended. The loop still performs its original reader calls.

For admitted rows, the original localization service writes a UTF16 string object and that object is appended without checking emptiness or whitespace. The original local output string starts empty; there is no separate post-localization success/trim gate in this body. After reading, the source deck is copied into the remaining deck and the first caption/effect pointers are selected. The [caption-start ASM](../../evidence/native/functions/00EC8190_AppLoadingScreen_StartNextCaption.asm) ([annotated C](../../evidence/native/functions/00EC8190_AppLoadingScreen_StartNextCaption.c)) consumes that remaining deck, selects through the original RNG helper and removes the chosen row.

## XML adapter and name comparison

Attach requires the adapter's unopened state and a nonzero stream; it retains/constructs its scanner as needed, resets tracking state and admits reading state 1. Exact-element search performs its existing name-map/position handling, advances and compares current names by raw UTF16 code units plus equal length. This root search is case-sensitive. Advance combines the scanner result, adapter validation and scanner-state gates and records the current name; it does not establish a DOM direct-child traversal rule. Current-name copying preserves code units and does not trim or lowercase. String-attribute reading requires a nonnull provider result and copies it; an empty nonnull string is admitted.

The Int32 helper requires the requested output count to be nonzero and the attribute/output pointer to be present. It calls the original comma tokenizer, requires exactly the requested token count, scans each token with UTF16 swscanf `%i` into successive four-byte outputs, totals successful conversions and checks adapter status. The LoadingText caller requests one value. `%i` is the original C-runtime conversion boundary; tokenizer handling of empty/trailing tokens and C-runtime locale/overflow are not recovered by this adapter alone.

The row-name comparer checks exactly its supplied count of UTF16 code units. Values below 256 pass through the original C tolower on their low byte; larger code units compare unchanged. It returns -1/0/+1. The LoadingText caller additionally checks equal lengths and supplies the minimum nonnegative length. This limited folding differs from general Unicode case folding.

## WinProc selection and remaining boundaries

The selected window helper enumerates winprocs through virtual +110 (initial previous pointer 0), queries each through virtual +C for interface 03EC1BC1, and returns the first nonnull match or zero at enumeration end. This is the startup Grow-interface context; the queried interface identity is distinct from a serialized effect class ID. No interpolation-kind/finite-value/duration validation occurs in this helper. The installed initializer reads the first selected duration, while the selected [timeline interpolator ASM](../../evidence/native/functions/00516F40_UiEffect_InterpolateTimelinePosition.asm) ([annotated C](../../evidence/native/functions/00516F40_UiEffect_InterpolateTimelinePosition.c)) supplies the original general interpolation behavior.
